扫描靶机查看端口：

使用dirsearch扫描网站

这里扫描出了有用的信息大概有README.MD、admin的登陆网页这两个

来到登陆页面

这里并不知道账户有哪些可以，可以forgetten这里验证用户存在性，最简单的尝试就是尝试这个网站的名称baker为用户名。然后结合README.MD说明文件给到提示大概就能够知道账户长啥样

拿到用户之后就需要来尝试爆破了，由于这个网站进行了设置，在默认页面就有提示，每一分钟就会删除一次wbce_blocking表，这个表大概功能就是用于记录尝试密码次数的主机IP的。所以很明确就是要进行爆破

这里可以尝试使用python写代码进行爆破，不过我说实话爆破的话似乎不是很管用说真的。也许是我写的不对，emm我也看过别人的wp，但是似乎都没有详细的去说有关于这个密码爆破。我的做法就是使用了burpsuite去爆破，但是并不是完全爆破是爆破了一段密码之后放行代理就能够直接进入网站管理员后台

之后利用漏洞：WBCE CMS 1.6.4 - Remote Code Execution - Multiple webapps Exploit

拦截

随便选择一个爆破类型

然后直接开始爆破不管时间限制了

可以看到三次之后就变成302了，这是被限制ip了。但是这时候点击放行请求并刷新页面你就会发现：

利用已知漏洞：WBCE CMS 1.6.4 - Remote Code Execution - Multiple webapps Exploit

当然也可以写一句木马触发

反弹shell

之后获取一下完整的shell，然后找漏洞就行，这里上来我就用sudo -l查看了一遍，然后发现了carol用户有一个权限ip命令可以用。那么其实可以很确定的思路就是从ip入手。可以去查看命令漏洞利用ip | GTFOBins

这里就可以读取到carol用户的id_rsa。

然后整理一下就可以得到完整的私钥

之后利用这个登录carol用户。

获取到了carol用户的权限之后还需要后去root用户，但是这里唯一的线索其实就只有/opt目录下，这个目录算是靶机的常客了。正好这下面有一个脚本的目录里面有monitor的一个elf文件。执行之后会返回当前用户的uid号等信息，所以我们可以在执行这个脚本之后利用ps aux来查看他有没有利用什么后台的东西，因为只是这个elf文件其实没啥用。emm不过拿去逆向其实也能看出东西来。但是这里的做题思路其实是利用ps来找线索。

我们就可以得到一个脚本文件在/usr/local/bin/check-monitor.sh

这个脚本其实就是一个看门狗，我们在每一次执行monitor的时候都会经过这个脚本，他会检查/tmp目录下是否存有相应的文件，这个文件有没有打上相应的标签，所有通过了才会执行。

其实这里的思路是先通过carol用户对/opt/scripts目录有更改权限，替换一个执行的漏洞脚本上去，然后会发现执行不了。之后通过执行原有的monitor文件来判断他还有一个“看门狗”脚本判断

所以这里我们就能够很快得出一个结论，如果要想拿到root权限就要骗过这个“安全狗”那么做法其实也很简单，我们可以通过写一个漏洞脚本可以是反弹shell也可以是更改sudo文件或者/etc/passwd文件来实现获取root权限。

我这里其实采用了最简单的做法就是通过修改sudo文件来实现root。当然这我也参考了别人的wp来自：Baker_scdyh.pdf的wp。
