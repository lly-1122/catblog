在Kubernetes中什么是污点？

污点是Kubernetes节点的一种属性标记，它起到“排斥”Pod的作用：

  • 给节点打上污点 = 节点拒绝某些Pod

  • 污点包含三个部分：key=value:effect

    • key:污点名称

    • value:污点值（可选）

    • effect:排斥效果

三种污点效果：

NoSchedule​

新Pod不会被调度到此节点

node-role.kubernetes.io/master:NoSchedule

PreferNoSchedule​

尽量不调度，但非强制

key=value:PreferNoSchedule

NoExecute​

不仅不调度，还会驱逐已有Pod

key=value:NoExecute

关于JumpServer

JumpServer谁快由python编写开源的跳板机系统，实现了跳板机应有的功能。基于ssh协议来管理，客户端无需安装agent。完全开源，GPL授权。

设计思路

  • 设计一个跳转网关，所有登录操作都从网关通过

    • 网关具有模拟终端功能，透明的中转ssh命令，一直吃tab，ctrl+a，ctrl-e等快捷键，网关既可以记录日志，又可以审计操作命令。

  • 设计一个认证模块

    • 为了实现认证功能，需要有个认证模板，认证信息存到数据库，用户使用跳板机首先需要认证。

  • 设计审计模块

    • 审计为了追踪，我们支持了在线监控，命令统计，录像回放功能，供管理员审计。

  • 用户和主机模块

    • 跳板机脱离不了用户和主机，所以这两个部分是基本的模块，另外我们将主机模块扩展，实现基本CMDB功能。

  • Web Terminal

    • 现在都流行Web操作一切，于是也实现了Web Terminal，供用户直接在线连接冯文强，这里实现使用了Tornado来完成的，Tornado实现websocket特别简单。

组件说明：

  • Jumpserver为管理后台，管理员可以通过Web页面进行资产管理、用户管理、资产授权等操作，用户可以通过Web页面进行资产登录，文件管理等操作是核心组件（Core），使用Django Class Based View风格开发，支持Restful API。

  • Luna为Web Terminal Server前端页面，用户使用Web Terminal方式登录所需的组件（WebTerminalView）该组件由团队自己通过Angular实现，Jumpserver只提供API，不负责后台渲染html等。

  • koko（CoCo）为SSH Server和Web Terminal Server。用户可以使用自己的账户通过SSH或Web Terminal访问SSH协议和Telnet协议资产。KoKo（最新版）是go版本的coco，新的Jumpserver ssh/ws server，重构了coco的ssh/sftp服务和Web Terminal服务（WebSFTPView）

  • Guacamole为RDP协议和VNC协议资产组件，用户可以通过Web Terminal来连接RDP协议和VNC协议资产。

Guacamole Apache跳板机项目，Jumpserver使用其组件实现RDP功能，Jumpserver并没有修改其代码而是添加了额外的插件，支持Jumpserver调用。

  • Jumpserver Python SDK

Jumpserver Python SDK，（KoKo）Coco目前使用该SDK与Jumpserver交互的一些功能。

端口说明

  • Jumpserver 默认端口为 8080/tcp 配置文件 jumpserver/config.yml

  • KoKo(Coco) 默认 SSH 端口为 2222/tcp, 默认 Web Terminal 端口为 5000/tcp 配置文件在 KoKo(CoCo)/config.yml

  • Guacamole 默认端口为 8081/tcp, 配置文件 /config/tomcat9/conf/server.xml

  • Nginx 默认端口为 80/tcp

  • Redis 默认端口为 6379/tcp

  • Mysql 默认端口为 3306/tcp

关于GitLab

GitLab是一个完整的DeveOps平台，以单一的Web应用程序形式，覆盖了从项目规划、源代码管理到CI/CD、监控和安全性的整个软件开发周期。它远不止是一个Git仓库管理器（如早期的GitHub、Bitbucket），其核心目标是缩短从想法到生产软件的周期时间，并在过程中增强协作、安全性和合规性。

核心定位：

  • 一体化平台：提供“开箱即用“的正套DevOps工具链，避免了为不同阶段集成多个独立工具所带来的复杂性和成本。

  • 端到端可见性

  • 自动核心

关于GitLab Runner

GitLab Runner是与GitLab CI/CD配合使用的执行期，用于在流水线中运行构建、测试、部署等任务。它支持多种执行环境（shell、dokcer、kubernetes）等，可部署在本地或云端
