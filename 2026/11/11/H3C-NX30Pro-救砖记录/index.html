H3C NX30 Pro 变砖自救完整记录：从“绿灯常亮”到 TTL 救砖复活

发表于2026-11-11|随记
|浏览量:

一篇写给自己的复盘，也给同样想给 NX30 Pro 刷 OpenWrt 的朋友当避坑指南。
从“刷机刷成砖”到“一根 TTL 线救回来”，全过程、原理（尽量讲人话）、命令、踩过的坑都在这里。

〇、背景：我是怎么把它刷成砖的

起因是想让手里的 H3C Magic NX30 Pro 跑 OpenWrt。当时参考了两篇思路不太一样的教程：

  • 一篇走“打包好的 uboot.bin，U-Boot 里一次加载就行”；
  • 另一篇走 OpenWrt 官方流程，要分别刷 preloader.bin（BL2）和 uboot.fip（U-Boot 本体）。

我图省事把两种混着用，结果只刷了 preloader.bin，没刷 uboot.fip。当时机器还在跑，以为没事；一断电重启——绿灯常亮、没 WiFi、网口没反应，进不了系统、也进不了 U-Boot、按键重置也没用。砖了。

为什么会“只刷一半就砖”

你可以把这台路由器想成一台小电脑，开机要经过几道“接力”：

  1. BootROM：焊死在芯片里的一小段程序，相当于主板上的 BIOS，永远在、也坏不了；
  2. BL2 / preloader：接下来接手的小程序，主要任务是把内存（DDR）点着、能用，相当于“点火/挂挡”；
  3. U-Boot（在 FIP 里）：相当于启动菜单，负责去找系统、把系统拉起来；
  4. 系统固件（在 ubi 的 fit 卷里）：真正的 OpenWrt 系统，相当于“发动机 + 车壳”。

我当时只刷了第 2 步（preloader），第 3 步（U-Boot / FIP）是空的/坏的。结果就是：“点火器”装上了，但“发动机”没装——BL2 想去 FIP 里拉起 U-Boot，发现啥都没有，于是卡死。所以“只刷 preloader、不刷 fip” = 必砖。

后面才发现，其实不用拆芯片、不用编程器，一根 USB-TTL 线就能救回来。

一、先判断：它到底砖在哪一层

变砖后先别急着拆芯片，第一件事是接 TTL 看有没有串口打印——这决定了怎么救。

现象：

  • 上电绿灯常亮，无 WiFi 广播，网口无反应；
  • 接上串口，有打印输出。

只要串口有输出，说明 BL2 还活着，问题出在 FIP（U-Boot）坏了读不出。串口里能看到类似：

这里的 image id 3 就是指 U-Boot（在 FIP 里）。看到这条基本可以确诊。

为什么这种情况“能救、还不用编程器”

关键在于 BootROM：它烧死在 SoC 里面，物理上坏不了，而且它内置了一个“UART 串口下载模式”。

打个比方：手机系统崩了开不了机，但主板的 BIOS 还在，你可以插个 U 盘进 PE 去修硬盘。 这里 BootROM 就是那个 BIOS，我们用 mtk_uartboot 通过串口，先把一个小程序“喂”进内存跑起来，等于先借一个临时系统，再去把闪存重新写干净。

判断口诀：
TTL 有输出 → 先别拆芯片，试 BootROM 救砖；
TTL 全静默 + 芯片发烫 / 认不出 → 才考虑编程器 / 换片。

二、拆机

拆外壳是整个流程里最“看手”的一步。最好备一根塑料撬棒；我工具还没到，就用了一套指甲护理套装——里面的指甲刀和扁平小件正好可以当撬棒。

手法要点：

  • 沿外壳缝隙慢慢撬，先撬开一点点，看清内部卡扣和电路板位置，再决定往哪撬；
  • 千万别撬到电路板本体，也别把 天线信号线（IPEX/U.FL 扣线） 扯断；
  • 耐心点，塑料卡扣撬断了外壳就合不严了。

三、准备 TTL 刷机工具

工具清单：

  • CH340G USB 转 TTL 模块 ×1（把电脑的 USB “翻译”成单片机能听懂的串口信号）
  • 母对母杜邦线 ×3（分别接 GND / RX / TX）
  • 烧录夹 ×1（强烈推荐；比用胶带贴稳太多）
  • 电脑、mtk_uartboot 工具、对应固件文件

买线时注意模块排针是公头还是母头。我买的是“母对母”杜邦线，正好配模块上的公针。

板子上的下载/调试口是扁平排针，用胶带贴很难固定，用烧录夹最省事。烧录夹探针间距选 2.54mm（2mm 会太窄顶不到），我那款是 3 排探针。

板子右上角丝印清晰标了 GND / TX / RX / VCC，旁边还有个复位键 S1：

用大白话解释这几个点：

  • 为什么 RX 要接 TX、TX 要接 RX（交叉）？ 串口是“一个说、一个听”：我这边的“话筒(TX)”要接到对面的“耳朵(RX)”，所以交叉，直连就变成俩人各说各话谁也听不见。
  • 为什么一定要接 GND？ 双方得先有“共同的电压基准”，不然信号对不上，这叫“共地”。
  • 为什么 VCC / 3.3V 一律不接？ 板子自己有电，你再灌一路 3.3V 进去，轻则抢电、重则烧口。只接三根信号/地线就够。

四、用 mtk_uartboot 进入 BootROM 下载模式

这一步时序最关键，顺序错了大概率握手失败：

  1. 先关掉 MobaXterm / PuTTY 等所有串口终端——它们会独占 COM 口，导致 mtk_uartboot 报 拒绝访问；
  2. 路由器先断电；
  3. 在电脑上运行 mtk_uartboot，屏幕出现 Waiting for device...；
  4. 这时才给路由器通电（顺序不能反：先等命令，后插电）；
  5. 等待握手完成，进入“内存里的 U-Boot”。

五、在 U-Boot 里重写 BL2 + FIP

进内存 U-Boot 后，先确认设备和分区，再写引导。

5.1 看设备 / 定义分区

通俗理解：mtd 就是“这块闪存的分区表”，mtd list 相当于问一句“你这块闪存切成哪几块、每块多大”。

如果这个 U-Boot 没内建分区表（只显示一个 spi-nand0 整片），就手动定义（设备名以 mtd list 显示的为准，一般 spi-nand0）：

坑：默认 mtdids 往往是 nmbm0=nmbm0（原厂 NMBM 布局）。如果报 Device nmbm0 not found，把左值也写成设备名本身 spi-nand0=spi-nand0，mtdparts 前缀也写 spi-nand0:。

常见分区偏移（这台机器的布局，供参考）：

分区 起始偏移 大小 说明
BL2 0x0000000 1 MB 一级引导 preloader
u-boot-env 0x0100000 512 KB U-Boot 环境变量
Factory 0x0180000 2 MB 无线校准 + MAC（只读）
FIP 0x0380000 2 MB U-Boot 本体
ubi 0x0580000 64 MB 固件区（fit 卷）

偏移=从整块闪存的第 0 个字节算起，这块分区“从哪儿开始、有多长”。 比如 Factory 从 0x180000（1.5MB 处）开始，长 2MB。写的时候必须精确对上，写错位置会把别的分区盖掉。

六、把系统固件写进 ubi 的 fit 卷

引导修好了，还要把“真正的系统”写进去。

通俗理解：ubi 是闪存里一块 64MB 的“大抽屉”，里面又分了几个“格子”；fit 就是专门放系统（内核+根文件系统打包体）的那个格子。U-Boot 开机就去 fit 这个格子里把系统拎出来启动。

方法一：U-Boot 菜单。 重启进 U-Boot 菜单，选 「Load production system via TFTP then write to NAND」（通常是第 5 项），选你的 sysupgrade FIT 镜像（.itb），它会自动建 fit 卷并写入。成功标志：

方法二：直接在 U-Boot 里用 ubi 命令写（ubi part ubi → ubi write）。

写完 reset，断电重开就能从 NAND 正常启动进系统了。

坑（fit 卷名）：ubootmod 的 U-Boot 只认名为 fit 的卷。如果某个固件的 sysupgrade 把镜像写进了别的卷名（例如 kernel），启动会报 Volume fit not found、一直回落到恢复模式。
救法：进 U-Boot 终端 ubi list 看卷名，ubi rename kernel fit 改回来，再 reset。

七、进系统后 WiFi 起不来？修复 Factory 校准

很多人把引导和固件救回来，却发现 WiFi 完全起不来，串口里是：

用大白话讲清楚“为什么”

  • Factory 分区存的是什么？ 是这颗 WiFi 芯片出厂时单独测出来的校准参数（每个频点该发多大功率、接收灵敏度、以及 MAC）。是“这台机器专属”的，不是通用值。
  • NAND 怎么存 0/1？ 靠给存储单元“充多少电荷”，从而改变一个叫 阈值电压 Vth 的东西。读的时候拿一个参考电压去比：比它低判 1、比它高判 0。
  • 什么是“半写”？ 上次写到一半被打断，某些单元的电荷处在“不三不四”的中间态——Vth 正好卡在参考线附近，读出来一会儿 1 一会儿 0，不稳。
  • ECC 是什么？ 每次写数据，芯片会顺便算一份“校验码”存旁边（OOB 区）。读的时候重算一遍对比，错得少能纠，错太多就报 -74（纠不回来）。

修复思路：读出 → 整块擦干净 → 原样写回。 擦除会把所有单元“归零/推到一边”，重写时再把电荷推到干脆的两侧、并重新算一份匹配的 ECC——相当于把“写花的黑板擦干净重写”。

重写后 phy0 / phy1 能正常注册，WiFi 就回来了。

只有 5G 不工作、2.4G 正常 的话，通常是 Factory 里 5G 那段校准数据丢了。可以用**另一台同平台（MT7981 + MT7976）路由器的 Factory 作为“供体校准”**补上（相当于借一台“同款发动机”的调校参数），注意把供体里的 MAC 改成自己的，避免冲突。

八、系统与网络的收尾设置

救活之后就可以当正常路由器用了。记录几个设置。

8.1 后台与 WiFi

  • 后台管理：http://192.168.10.1，root 密码 Key-1122（公开无妨，反正外网连不进来；建议自己再改强一点）；
  • WiFi：Manbo2（5G）/ Manbo2-2.4G，WPA2-PSK，密码 Key-1122。

8.2 LAN 网段：换成 192.168.10.1 避免冲突

如果这台路由的 WAN 是“无线中继 / 接在另一台路由器后面”，而上游网关也是 192.168.1.1，就会和本机默认的 LAN 192.168.1.1 撞车（两个网段一模一样，路由会懵），导致 LAN 下设备上网异常。改成别的网段即可：

改 LAN 网段会让当前连接断开：电脑要么重新 DHCP 拿 192.168.10.x，要么手动设静态 192.168.10.2，再访问新后台地址。

十、验收清单

救完之后逐项确认：

  • 断电重开能自动进系统（不是每次都要手动）；
  • 2.4G / 5G 都能连、能上网；
  • MAC 已设回真实值；
  • Factory 读取稳定（可 md5sum 连读两次对比一致）。

十一、经验 & 踩坑清单

  1. 别混用教程：不同教程的刷机流程/文件不一样，只刷 preloader 不刷 fip 必砖。
  2. 刷机前先搞懂“刷的是哪一块”：BL2 / FIP(U-Boot) / 固件(FIT) 三层，缺一不可。
  3. TTL 有输出 = 大概率能免拆芯片救，先别上编程器。
  4. mtk_uartboot 时序：先断电 → 出 Waiting for device → 再插电。
  5. COM 口独占：串口终端和 mtk_uartboot 不能同时占用。
  6. mtd write 必须 4 参数，命令逐条敲、核对偏移与大小。
  7. WiFi 起不来先查 Factory 的 ECC，读出→擦除→重写往往能救。
  8. 只有 5G 不行 → 多半是 Factory 里 5G 校准缺失，用同平台供体补。
  9. 救完把 MAC 设回真实值，别让它随机漂。
  10. 保留整机备份（引导 + Factory + 固件），最坏也能还原。
